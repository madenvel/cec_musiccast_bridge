# HDMI-CEC to MusicCast bridge

Use a TV remote to control a Yamaha MusicCast amplifier connected to the TV's
optical audio output. A Raspberry Pi (or a supported USB CEC adapter) presents
an HDMI-CEC audio system to the TV and forwards power, input and volume commands
to the receiver over the local network. Tested originally with a Raspberry Pi 4,
Samsung TV and Yamaha R-N602.

Enable HDMI-CEC on the TV, select the bridge as its audio output and enable
simultaneous optical audio output. HDMI carries control commands; the optical
cable carries the audio. Enable network standby on the receiver so discovery
and power-on commands work while it is in standby.

## Discover a receiver

```sh
cec-musiccast-bridge --discover
```

This sends SSDP MediaRenderer searches on active IPv4 multicast interfaces and
verifies responders using the Yamaha Extended Control `system/getDeviceInfo`
API. It prints a JSON array containing `address`, `device_id` and `model_name`,
without opening the CEC adapter or changing receiver settings. Exit status is 1
if no receiver is found. The default search listens for 5 seconds, followed by
HTTP probes with a 3-second limit per candidate. Use `--interface LOCAL_IPV4`
to select a local network interface.

Omit `--address` (or use `--address auto`) to discover automatically. If there
is more than one receiver, select one by its stable ID:

```sh
cec-musiccast-bridge --device-id AC44F242F02A --input optical1 --volume 90
```

The ID is case-insensitive. With no selector, the bridge requires exactly one
receiver; it does not choose arbitrarily. Pinning a device ID is recommended
so the choice remains stable across service restarts. A fixed address is also
supported for networks that block multicast:

```sh
cec-musiccast-bridge --address 192.168.50.201 --input optical1 --volume 90
```

The bridge checks the selected receiver every 30 seconds. On connection loss,
it pauses commands and, in automatic mode, searches for that same device ID
again, retrying every 10 seconds while offline. Failed commands are not replayed.
An explicitly configured address is retried without SSDP. At initial startup,
a missing or ambiguous receiver causes a nonzero exit; systemd retries after
10 seconds. Discovery is IPv4 and stays on the local multicast network.

## Install on Debian or Raspberry Pi OS

Build a package for the target's Debian release and architecture (for example,
`arm64` for 64-bit Raspberry Pi OS). Runtime dependencies are resolved by apt:

```sh
sudo apt install ./cec-musiccast-bridge_0.2.0-1_arm64.deb
# Equivalent convenience script:
./scripts/install-deb.sh ./cec-musiccast-bridge_0.2.0-1_arm64.deb
```

The package contains:

- `/usr/bin/cec-musiccast-bridge` and its manual page;
- `/etc/cec-musiccast-bridge.conf`, preserved as a Debian conffile on upgrades;
- `cec-musiccast-bridge.service`, enabled and started on installation;
- a dedicated `cec-musiccast` system user with `video` and `dialout` access;
- udev rules for kernel CEC devices and Pulse-Eight USB adapters;
- maintainer scripts generated by debhelper to start/restart/stop the service,
  reload udev rules and clean up on package removal or purge.

Edit the configuration for your receiver and restart:

```ini
address = auto
device-id = AC44F242F02A
input = optical1
volume = 90
discovery-timeout = 5
```

Volume uses the receiver's Yamaha units, **not a percentage**. The default 90
matches the original bridge; choose the appropriate power-on level for your
receiver. The generic package does not pin the example device ID.

```sh
sudo systemctl restart cec-musiccast-bridge
systemctl status cec-musiccast-bridge
journalctl -u cec-musiccast-bridge -f
```

Command-line values override config values. The config file is read only when
`--config PATH` is supplied; the packaged service supplies it automatically.
Unknown config keys and invalid values are rejected.

To migrate a manually installed service, back up its unit and settings before
installing the package. A unit in `/etc/systemd/system` or a drop-in can override
the packaged unit; inspect `systemctl cat cec-musiccast-bridge` and remove the
obsolete override after transferring its arguments to the config. A previous
unit in `/usr/lib/systemd/system` is replaced by the package. Keep only one
bridge process connected to the CEC adapter.

```sh
sudo apt remove cec-musiccast-bridge  # stops/disables it; retains config
sudo apt purge cec-musiccast-bridge   # also removes package configuration
```

The system account is deliberately retained on purge to avoid UID reuse.

## Build and test

On Debian or Raspberry Pi OS:

```sh
sudo apt install build-essential debhelper libcec-dev libcurl4-openssl-dev \
  libboost-program-options-dev nlohmann-json3-dev python3
make
make test
./scripts/build-deb.sh
```

The build produces `cec`; the Debian package installs it under the descriptive
name `cec-musiccast-bridge`. `make test` exercises SSDP response parsing, stable
selection, HTTP/API errors, timeouts and config precedence without CEC hardware.
The `.deb`, debug symbols and build metadata are written to the parent directory.
Debhelper derives runtime library dependencies from the built executable and
manages service lifecycle scripts. `make install DESTDIR=...` stages the binary
and configuration only; use the Debian package for the complete service setup.

For cross builds, install the target's development libraries and compiler, then
use `./scripts/build-deb.sh -a arm64`. Native tests run on native builds; cross
builds skip execution of target binaries. CI builds and tests packages natively
on both amd64 and arm64.

HTTP requests have connection and overall time limits. Invalid JSON, failed
status requests and missing CEC hardware produce diagnostics instead of a
successful but inactive service. SIGINT and SIGTERM close the CEC adapter.

## Build a tagged version in CI

After committing and pushing the source and workflow, push a version tag:

```sh
git tag v0.3.0
git push origin v0.3.0
```

The **Debian packages** GitHub Actions workflow checks out that tag, sets the
Debian changelog version from it, then builds and tests native amd64 and arm64
packages for Debian 13 (trixie). There is no need to bump `debian/changelog`
manually before tagging. `v0.3.0` (or `0.3.0`) produces
`cec-musiccast-bridge_0.3.0-1_arm64.deb` and the corresponding amd64 package.
Prerelease tags such as `v0.3.0-rc.1` produce `0.3.0~rc.1-1`, which Debian sorts
before the final release. Tags must use `MAJOR.MINOR.PATCH`, optionally prefixed
with `v` and followed by a prerelease suffix.

Download packages and debug symbols from the workflow run's **Artifacts**
section; each artifact name includes the version and architecture. To rebuild
an existing tag, use **Run workflow** and enter it in the optional **tag** input.
Branch and pull-request builds continue using the checked-in changelog version.
The workflow uploads build artifacts; it does not publish a GitHub Release.
